# Data Model: Personal Expense Tracker

## Expense

One saved personal spending entry. Repeated entries with the same values are allowed and
remain distinct records.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | string | Yes | Non-empty and unique within the stored collection. Generated by the application. |
| `amount` | number | Yes | Integer rupees in the inclusive range 1 through 9,007,199,254,740,991. |
| `category` | string | Yes | Exact member of the fixed category set below. |
| `date` | string | Yes | Real Gregorian calendar date in `YYYY-MM-DD`; today or earlier at add/edit time. |
| `description` | string | Yes | Trimmed text, empty string when omitted, at most 250 Unicode code points. |
| `createdAt` | number | Yes | Non-negative integer epoch milliseconds assigned when the record is added; unchanged on edit. |

### Fixed Categories

`Food`, `Transport`, `Housing`, `Utilities`, `Healthcare`, `Shopping`, `Education`,
`Entertainment`, `Travel`, `Other`.

Category matching is exact. User-created categories are not supported.

## Stored Envelope

The localStorage value is one JSON string containing an envelope:

```json
{
  "format": "expense-tracker",
  "schemaVersion": 1,
  "records": [
    {
      "id": "expense-id",
      "amount": 1250,
      "category": "Food",
      "date": "2026-11-10",
      "description": "Lunch",
      "createdAt": 1794312000000
    }
  ]
}
```

The canonical key is `expense-tracker:data`. A missing key represents first-run empty
state. The version-1 reader validates the envelope, field types, allowed values, unique
IDs, amount bounds, description length, and real calendar dates. It rejects the complete
document if any record is invalid; it does not partially load or normalize corrupt data.
The date's not-in-the-future rule is checked when adding or editing, not when reading, so a
valid saved date remains readable if the device's clock later changes.

## Derived View State

Filters and totals are not persisted.

- **Filters**: optional exact category and optional calendar month in `YYYY-MM` form.
- **Filtered records**: match both active filters (AND); a cleared filter imposes no
  restriction.
- **Order**: date descending, then `createdAt` descending, then stored append order
  descending for timestamp ties. Editing does not change `createdAt` or append position.
- **Totals**: exact integer sums for the filtered list and each category represented in
  that list. Use `BigInt` for derived sums; do not store BigInt values in the JSON envelope.

## Validation and Lifecycle

1. A form draft is untrusted text.
2. Pure validation trims surrounding whitespace, checks required fields and exact category
   membership, parses the amount, validates the real calendar date and future-date rule,
   and returns either normalized data or field-keyed errors.
3. A valid add receives a unique ID and creation timestamp. A valid edit preserves ID and
   creation timestamp.
4. The controller builds the candidate record collection and asks the repository to save
   it. The controller publishes the new in-memory state only after persistence succeeds.
5. A confirmed delete follows the same persist-before-commit rule. Canceling is a no-op.
6. Invalid form data never reaches storage. Corrupt stored data blocks mutations until it
   is readable again; failed writes preserve the previous committed state.

## Module Functions

| Module | Public responsibility |
|---|---|
| `src/domain/expense-validation.js` | Export fixed categories, `validateExpenseInput(input, { today })`, and calendar-date validation. Return normalized values or field-specific errors; perform no DOM or storage access. |
| `src/domain/expense-queries.js` | Export `sortExpenses(records)`, `filterExpenses(records, filters)`, and `calculateTotals(records)`. Pure functions; totals use exact integer arithmetic. |
| `src/storage/expense-repository.js` | Export `createExpenseRepository({ getStorage })` with `load()` and `save(records)`. Validate the versioned envelope and return explicit success/error results. |
| `src/application/expense-controller.js` | Export a controller factory that initializes state and coordinates add, edit, confirmed delete, filter changes, persistence, and rendering. Inject date, clock, ID, and rendering functions for deterministic tests. |
| `src/ui/bind-events.js` | Bind form, filter, edit, and delete events to controller operations; keep event parsing and focus management out of domain logic. |
| `src/ui/render.js` | Render application state, inline errors, empty states, totals, and storage errors using safe DOM text APIs. Do not access storage or decide business rules. |
| `src/main.js` | Composition root: create repository/controller, initialize stored data, and mount the UI. |

## Error Results

- `load()` returns either `{ ok: true, records }` or an explicit error result such as
  `corrupt-data` or `storage-unavailable`.
- `save(records)` returns success only after `setItem` completes. A thrown access, quota,
  or serialization error returns an explicit failure; it must not be hidden or shaped as
  success.
- The UI distinguishes field validation errors from global recovery/persistence errors.
